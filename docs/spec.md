# Joshfield 포트폴리오 사이트 화면 기획서

2026-11-11 · @josh

## 1. 문서 개요

이 사이트의 컨셉은 **"넓은 들판 위의 작은 사람, 흐림에서 선명함으로"**입니다. 스크롤은 들판을 걷는 여정이고, 푸터는 그 끝에 닿는 지평선입니다.

| 항목 | 내용 |
|---|---|
| 목적 | 웹·모바일 UX/UI 디자이너로서의 작업과 사고 과정을 보여주는 개인 포트폴리오 |
| 주요 방문자 | 채용 담당자·디자인 리드(빠르게 훑음), 교수·연구실(연구 맥락을 깊게 읽음), 동료 디자이너 |
| 범위 | 데스크톱·태블릿·모바일 반응형 웹, 6개 화면 + 공통 컴포넌트 2개 |
| 핵심 성공 기준 | 30초 안에 "누구인지, 무엇을 잘하는지" 전달 · 대표 프로젝트 상세까지 2클릭 · 푸터에서 연락으로 이어짐 |

**전제(확정·가정)**: 이름은 Josh, 사이트 이름은 Joshfield(3장)입니다. 프로젝트는 실제 1개 + 가제 4개, 총 5개 슬롯으로 잡았고(P-02), 나머지는 내용이 생기면 채웁니다. 국문·영문을 병행하고(7-6), 제작은 Claude Code에 맡깁니다(7-7).

**레퍼런스 번호**: 첨부 순서대로 1~4는 푸터 레퍼런스, 5~10은 무드 레퍼런스로 봤습니다. (말씀은 5~9였지만 첨부가 10장이라 마지막 색연필 그림도 무드에 넣었습니다.)

- R1 sequel: 코발트 블루 바탕 + 크림색 판화풍 사막, 말 탄 사람
- R2 Acme: 찢어진 종이 아래로 드러나는 잔디밭과 책상에 앉은 사람
- R3 Ironclad Labs: 노이즈 낀 파스텔 그라데이션 + 무지갯빛 언덕
- R4 Dia: 오프화이트 바탕, 모노스페이스 대문자 링크, 흐릿한 무지개 지평선
- R5 역광 속 말 떼와 아이의 실루엣(영화 스틸컷 느낌)
- R6 안쪽으로 말린 잔디 원 + 하늘, 달리는 작은 사람들
- R7 초록·하늘색 대각선 모션 블러
- R8 파란 소용돌이 블러 + 주황 빛줄기
- R9 눈밭 위에서 손잡고 도는 사람들, 장노출 블러
- R10 색연필 풍경, 흐린 인물 옆의 점 잇기(dot-to-dot) 윤곽

## 2. 레퍼런스 분석

열 장을 관통하는 공통 언어는 다섯 가지입니다: 지평선, 작은 인물, 움직임(블러), 아날로그 질감, 파랑·초록 중심의 절제된 색. 이 다섯 가지를 사이트 전체의 규칙으로 삼습니다.

### 2-1. 푸터 레퍼런스(R1~R4)에서 가져올 것

| 레퍼런스 | 구조 | 좋은 점 | 이 사이트에 가져올 것 |
|---|---|---|---|
| R1 sequel | 위: 로고·연락처·링크 4열 / 아래 40%: 판화 사막 일러스트 | 두 가지 색(코발트+크림)만으로 끝내는 듀오톤, 세리프 이탤릭의 문학적 톤 | **메인 방향.** 푸터 하단을 일러스트 풍경으로 채우고, 그 안에 "나"를 뜻하는 작은 인물을 둔다 |
| R2 Acme | 종이가 찢어진 경계선 아래에 실사 풍경이 드러남 | 본문(종이)과 푸터(세계)의 경계가 하나의 사건처럼 느껴짐 | 본문 → 푸터 전환부를 직선이 아닌 **유기적인 경계선**(산 능선)으로 처리 |
| R3 Ironclad Labs | 상단 정보 + 가는 구분선 + 하단 추상 언덕 | 노이즈(grain, 자글자글한 입자감)가 디지털 그라데이션을 종이처럼 보이게 함 | 사이트 전체에 **엷은 그레인 텍스처** 오버레이 |
| R4 Dia | 마지막 CTA(행동 유도 문구) → 모노스페이스 링크 → 무지개 지평선 | 세리프 헤드라인과 작은 모노스페이스 라벨의 대비, 해가 뜨는 듯한 끝맺음 | 푸터 직전에 **한 줄 질문형 CTA** + 모노스페이스 라벨 체계 |

네 푸터의 공통점은 **"위는 정보, 아래는 풍경"** 구조입니다. 푸터를 링크 모음이 아니라 페이지의 엔딩 장면으로 씁니다. 포트폴리오에서는 방문자가 끝까지 내려왔다는 뜻이니, 이 장면이 기억에 남는 마지막 인상이 됩니다.

### 2-2. 무드 레퍼런스(R5~R10)에서 가져올 것

| 레퍼런스 | 핵심 감각 | 사이트에서 쓰는 곳 |
|---|---|---|
| R5 역광 속 말과 아이 | 역광(빛을 등지고 찍어 윤곽만 남는 사진), 따뜻한 금빛, 질주하는 움직임 | 저녁 시간대 푸터의 호박색 하늘, 강조색 하나 |
| R6 잔디 원과 하늘 | 큰 여백 속 작은 문장 하나, 동그란 창, 작게 달리는 사람들 | 메인 히어로의 **원형 창** 모티프와 작은 세리프 문장 |
| R7 대각선 블러 | ICM(Intentional Camera Movement, 일부러 카메라를 움직여 찍는 기법)의 속도감 | 섹션 사이 전환 이미지, 로딩 화면 |
| R8 소용돌이 블러 | 파란 흐름 속 주황 빛줄기 하나 | "파란 중심 + 주황 점 하나"라는 색 비율 규칙 |
| R9 원을 그리며 도는 사람들 | 장노출(셔터를 오래 열어 움직임을 흔적으로 남기는 촬영) 속 협업의 느낌 | 협업 프로젝트의 팀 소개, About의 "일하는 방식" |
| R10 점 잇기 윤곽 | 흐린 인물 옆에 번호 붙은 점으로만 그려진 "빈자리" | **디자인 프로세스 내비게이션**(점을 잇듯 단계를 잇는다), 404 페이지 |

무드 레퍼런스의 줄기는 **흐림(blur)과 선명함(focus)의 대비**입니다. 디자인 과정도 모호한 문제에서 시작해 선명한 해답으로 가므로, 이 대비를 인터랙션 규칙으로 바꿉니다.

**주의**: R5는 영화 스틸컷으로 보이고, R1·R2는 다른 브랜드의 작업물입니다. 분위기 참고용으로만 쓰고, 사이트에 들어갈 이미지와 일러스트는 직접 찍거나 그리거나 라이선스를 확인한 자료를 쓰세요.

## 3. 컨셉 & 디자인 원칙

컨셉 문장: **"흐릿한 들판에서 출발해 선명한 지평선에 닿는 여정."** 작업물은 매번 흐린 상태에서 나타나 초점이 맞고, 사이트의 끝에는 작은 내가 서 있는 풍경이 기다립니다.

**사이트 이름 후보** (이름: Josh)

| 이름 | 뜻 | 컨셉 연결 | 한 줄 소개(EN) |
|---|---|---|---|
| **Joshfield (확정)** | Josh + field(들판). Springfield처럼 지명으로 들림 | 사이트 전체가 "Josh의 들판"이라는 장소가 되고, 푸터 풍경은 그 들판의 끝 | A field of work by Josh |
| Josh, in Focus | 초점이 맞은 Josh | 흐림→선명 인터랙션과 바로 연결 | Bringing blurry problems into focus |
| Josh Afield | afield = 들판으로, 먼 곳으로 | 걸어가는 인물, 여정 | Notes from the field |
| Joshwalks | Josh가 걷는다 | 푸터의 걸는 인물이 곧 이름 | One step at a time |
| Dot to Josh | 점을 이어 Josh에 닿음 | 점 잇기 프로세스 | Connecting dots into products |

최종 이름은 **Joshfield**입니다. 짧은 고유명사라 기억에 남고, 들판·지평선·걸어가는 인물 모티프를 이름 하나로 묶어줍니다. 푸터 끝에 "You've reached the edge of Joshfield." 같은 문구로 이름을 다시 불러올 수 있어요. 도메인(joshfield.com 등)은 사용 가능한지 직접 확인해야 하고, 이미 쓰이고 있다면 .design, .studio, .kr 같은 도메인도 검토하세요.

**키워드 5**

1. 지평선(Horizon): 페이지의 끝은 항상 풍경. 가로로 긴 여백과 수평선 구도.
2. 작은 인물(Small figure): 사람은 화면 속 작은 점. 디자이너 자신을 낮춰 작업을 돋보이게 하는 태도.
3. 흐림→선명(Blur to focus): 모호한 문제를 선명하게 풀어내는 디자인 과정의 은유.
4. 점 잇기(Connect the dots): 리서치부터 테스트까지 번호 붙은 단계를 잇는 서사.
5. 아날로그 질감(Analog grain): 판화·색연필·필름 그레인. 차가운 UI에 손의 온도를 더함.

**디자인 원칙 4**

| 원칙 | 뜻 | 지키는 방법 |
|---|---|---|
| 작업이 주인공 | 분위기는 무대, 작업은 배우 | 프로젝트 이미지 주변에는 텍스처·장식을 올리지 않음 |
| 흐림은 이미지에만 | 글자는 언제나 선명 | 텍스트에는 blur 효과를 적용하지 않음, 블러 위 글자는 대비 확보 |
| 색은 절제 | 파랑·크림 중심, 주황은 화면당 한 곳 | 70% 크림 / 25% 블루·그린 / 5% 주황 |
| 느리지만 답답하지 않게 | 서정적인 움직임, 빠른 탐색 | 연출은 600ms 이하, 내비게이션은 즉시 반응 |

### 4-3. 텍스처와 이미지

- **그레인 오버레이**: 화면 전체에 노이즈 이미지를 불투명도 4~6%로 고정. 작은 타일 이미지를 반복해 용량을 아낌.
- **판화 일러스트**: 푸터 풍경은 R1처럼 선으로 새긴 듯한 듀오톤. 직접 그리거나 사진을 판화 필터로 변환한 뒤 손으로 다듬음.
- **색연필 드로잉**: About·404의 일러스트는 R10처럼 색연필 질감.
- **ICM 사진**: 직접 찍은 모션 블러 사진 3~5장을 섹션 전환·로딩에 사용. 셀프 촬영이라 저작권 문제가 없고, 포트폴리오의 개성이 됨.
- **프로젝트 이미지**: 장식 없이 선명하게. 목업 배경은 paper 또는 sky 단색으로 통일해 여러 프로젝트가 한 집안처럼 보이게 함.

## 5. IA·사이트맵·유저 플로우

메뉴는 4개, 깊이는 최대 2단계입니다. IA(Information Architecture, 정보 구조)는 콘텐츠를 어떻게 묶고 어디에 둘지 정하는 설계인데, 포트폴리오는 방문 시간이 짧아서 얕고 넓은 구조가 유리합니다.

```text
Home (/ · P-01)
├─ Work 목록 (/work · P-02)
│   └─ Work 상세 (/work/[slug] · P-03)  ↻ 하단 Next Project로 다음 상세로
├─ Research (/research · P-04)
├─ About (/about · P-05)
└─ Contact (#footer · C-02)  — 별도 페이지 없이 푸터로 이동

모든 화면 공통: C-01 헤더 · C-02 푸터 · P-06 404 페이지
```
*사이트맵 · 화면 6개 + 공통 컴포넌트 2개*

Contact는 별도 페이지 대신 푸터로 보냅니다. 어느 화면에서든 끝까지 내리면 연락처가 있어, 푸터가 공통 도착지 역할을 합니다.

### 유저 플로우

유저 플로우(User flow)는 방문자가 목적을 이루기까지 거치는 화면 순서입니다.

**A. 채용 담당자 (약 3분 체류)**

1. Home 히어로와 자기소개에서 직무와 소속 파악
2. Selected Work 카드 클릭
3. 상세 상단 메타 표 + TL;DR만 읽고 판단
4. Next Project로 한 개 더 보기
5. 푸터에서 이메일 복사 또는 한 줄 메시지

**B. 교수·연구실 (약 10분 체류)**

1. Home에서 헤더 RESEARCH 클릭
2. 논문 행을 펼쳐 초록 읽기, PDF 열기
3. About에서 학력·연구 관심사 확인
4. CV 다운로드 후 푸터로 연락

두 플로우 모두 끝은 푸터입니다. 그래서 푸터는 장식이 아니라 전환(연락)이 일어나는 화면으로 설계합니다.

## 7. 반응형·인터랙션·접근성·성능

연출이 많은 사이트일수록 "효과를 끔 수 있는지"와 "모바일에서 빠른지"가 평가를 갈라요. 포트폴리오를 보는 디자인 리드는 이 부분을 실력으로 읽습니다.

### 7-1. 브레이크포인트와 그리드

브레이크포인트(breakpoint)는 화면 폭에 따라 레이아웃이 바뀌는 기준점입니다.

| 구분 | 화면 폭 | 컬럼 | 좌우 여백 | 거터(열 간격) |
|---|---|---|---|---|
| Mobile | 0–767px | 4 | 20px | 16px |
| Tablet | 768–1279px | 8 | 32px | 20px |
| Desktop | 1280px 이상 | 12 (콘텐츠 최대 1200px) | auto | 24px |

### 7-2. 화면별 반응형 차이

| 화면 | 데스크톱 | 모바일 |
|---|---|---|
| 헤더 | 메뉴 4개 노출 | MENU 버튼 → 전체 화면 메뉴 |
| Home 히어로 | 원형 창 지름 화면 높이의 70% | 화면 폭의 85%, 확대 연출은 짧게 |
| Work 목록 | 리스트 보기에서 썸네일이 커서를 따라옴 | 리스트 행마다 작은 썸네일을 고정 표시 |
| 상세 점 내비 | 왼쪽 세로 고정 | 상단 가로 진행 막대 |
| 푸터 | 링크 4열 + 풍경 | 링크 2열로 접고, 풍경은 인물이 가운데 오도록 크롭. 시차 효과는 약하게 |

### 7-3. 터치·호버 차이

- 마우스 호버가 없는 터치 기기에서는 Hover focus 대신, 카드가 화면 중앙에 오면 자동으로 선명해지도록 함.
- 터치 영역은 최소 44×44px. 모노 12px 링크도 클릭 영역은 넓게.

### 7-4. 접근성

- **모션 줄이기**: 운영체제에서 "동작 줄이기"를 켜 둔 사용자(CSS `prefers-reduced-motion`)에게는 블러·시차·확대 연출을 끄고 투명도 전환만 남김.
- **글자 대비**: 4-1의 메모대로 본문 4.5:1 이상. 풀사진 위 문구에는 어두운 오버레이를 깔.
- **키보드 이동**: Tab 키로 모든 링크에 갈 수 있고, 포커스 표시(현재 선택 위치 테두리)는 dusk색 2px로 분명하게.
- **대체 텍스트(alt)**: 작업 이미지에는 내용을 설명하는 alt, 장식 이미지(그레인·풍경 레이어)는 빈 alt로 화면낭독기가 건너뛰게 함.
- **점 내비게이션**: 점마다 섹션 이름을 라벨로 달아, 번호만 있어도 무엇인지 알 수 있게 함.

### 7-5. 성능

- 이미지는 AVIF/WebP(용량이 작은 차세대 이미지 포맷)로, 화면 밖 이미지는 지연 로딩(보일 때 불러오기).
- Focus-in 효과는 작은 흐린 미리보기 이미지를 먼저 보여주고 원본으로 교체하는 방식으로 구현하면 로딩 대기가 자연스럽게 연출이 됩니다.
- 푸터 풍경은 통짜 비트맵 대신 레이어별 SVG 또는 압축 PNG. 그레인은 작은 타일 반복.
- 목표: 첫 화면의 가장 큰 요소가 2.5초 안에 표시(LCP, Largest Contentful Paint).

### 7-6. 언어 병행 (KO / EN)

| URL | 국문 `/` · 영문 `/en` (예: `/en/work/project-01`) |
| 기본 언어 | 국문. 브라우저 언어가 영어면 첫 방문 때 상단에 "View in English" 안내만 띄우고, 자동으로 이동하지는 않음 |
| 전환 | 헤더의 KO / EN, 같은 페이지의 다른 언어 버전으로 이동 |
| 번역 범위 | 전 화면. 케이스 스터디는 영문 요약판으로 시작해도 됨 |
| 항상 영문 | 메뉴, 모노 라벨(ROLE, DURATION 등), 프로젝트 메타 |
| 서체 | 영문 Instrument Serif / Inter, 국문 마루 부리 / Pretendard. 한 문장에 섞일 때는 영문 서체가 영문 글자를 담당하도록 지정 |
| 길이 차이 | 영문이 더 길어지는 경우가 많아, 버튼·라벨 폭은 영문 기준으로 설계 |

### 7-7. 제작 도구: Claude Code

Claude Code는 코드를 직접 작성하고 실행하는 AI 코딩 도구라서, 노코드 도구보다 점 잇기나 시간대 하늘 같은 맞춤 연출을 구현하기 쉽습니다. 대신 지시가 구체적일수록 결과가 좋아지므로, 이 기획서를 그대로 넘기는 것부터 시작하세요.

**권장 기술 스택**(사이트를 만드는 도구 조합)

| 역할 | 선택 | 쉬운 설명 |
|---|---|---|
| 프레임워크 | Next.js + TypeScript | 페이지와 주소 체계를 갖춘 React 기반 웹 프레임워크 |
| 스타일 | Tailwind CSS | 4장의 커러·타이포 토큰을 설정 파일에 등록해 일관되게 사용 |
| 모션 | Framer Motion (필요하면 GSAP ScrollTrigger) | Focus-in, 시차, 점 잇기 같은 스크롤 연출 |
| 다국어 | next-intl | `/`와 `/en` 경로, 언어별 문구 파일 분리 |
| 콘텐츠 | MDX 파일 (프로젝트당 국문·영문 1개씩) | 마크다운에 화면 컴포넌트를 섞어 쓰는 형식. 가제 4개는 더미 MDX로 시작해 나중에 교체 |
| 배포 | Vercel | GitHub에 올리면 자동으로 공개, 개인 포트폴리오는 무료 플랜으로 충분 |

**Claude Code에 맡기는 순서** (한 번에 한 단계씩, 확인하고 다음으로)

1. 이 기획서를 Markdown으로 내보내 프로젝트 폴더에 `docs/spec.md`로 넣기. 디자인 토큰(4장)과 규칙(3장 원칙, 7-4 접근성)은 `CLAUDE.md`에 요약. CLAUDE.md는 Claude Code가 작업마다 먼저 읽는 프로젝트 안내 파일입니다.
2. 프로젝트 생성 + 토큰·서체·그레인 오버레이 + C-01 헤더
3. C-02 푸터 (풍경 레이어와 걸어가는 인물은 임시 도형으로)
4. P-01 Home → P-02 Work 목록(슬롯 5개, 더미) → P-03 상세 템플릿 + 점 내비게이션
5. P-04 Research, P-05 About, P-06 404
6. 영문(`/en`) 연결과 문구 파일
7. 접근성(동작 줄이기, 키보드)·성능 점검 후 Vercel 배포

지시 예시: "docs/spec.md의 C-02 푸터를 구현해줘. 경계선은 산 능선 SVG, 풍경은 3개 레이어 시차, 가운데 걸어가는 인물은 스크롤에 맞춰 이동. prefers-reduced-motion이면 움직임을 모두 꺼줘. 끝나면 로컬에서 확인하는 방법도 알려줘."

푸터 풍경과 걸어가는 인물은 코드보다 그림이 필요한 부분입니다. 직접 그리거나 따로 제작해 SVG로 넣어야 품질이 좋으니, Claude Code에는 임시 도형으로 자리만 잡게 하고 나중에 교체하세요.
